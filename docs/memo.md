# やりたいこと

広大なフィールドの中で資源クラスタ（資源が集中して存在する地点）を探索して見つける。考えなしに探索をすると、他のboidが探索したところを探索しちゃって効率が悪かったり（フェロモンという要素を導入する動機）、途中で燃料が尽きて帰還できなくなったり（適切な位置に補給所を建てつつ探索範囲を広げる戦略の自然な導入）。要検討:補給所を随所に建てるなら探索済みを表すフェロモンの存在意義は薄いのでは？まずは補給所を建てながら探索をするのを試したほうがいいかもしれない。

↑で資源クラスタを見つけたら効率的に資源を回収する

デバッグ用にboidの視界範囲を描画したい。GUIに描画するかどうかのチェックボックスも欲しい。

基地や補給所ごとに資源を管理しないようにしたい。資源はグローバルに管理して、基地や補給所に資源を回収したらグローバルに数が増加するようにしたい（グローバル管理なので基地や補給所に表示される資源数の描画もなくなる）


# 考えたいこと

現状（最新のコミットIDを付記して記録しておきたい）、boidはcargoがない状態で資源に触れると勝手に資源を取得して、資源を持っている状態で基地または補給所に触れると勝手に置いちゃう。
もしも、いずれ回収及び提出を制御したくなったらこの挙動を変える必要あり。特に勝手に拾っちゃうのは致命的かつユーザーにかなり面倒な実装を求めることになりそう。
雑な提案：boidに、もしも~~に触れたら勝手に回収するホワイトリスト変数と、勝手に基地または補給所に提出してよいかを制御するフラグ変数をもたせてこれを任意のステップで制御可能にする。
要検討：今後boidにどんな制御要素を追加していくかわからない状況でこれに決めてしまっても良いものか？保留にしたほうが良いか？


# 完了済み

- 広域探索（フェロモンなし版）を`scenarios/frontier.ts`として試作した
  （コミット`913458a`、その後`7a07d32`でv2として書き直し）。既存シナリオが全て使って
  いた「資源はこの方向にある」という決め打ち(`EXPLORE_DIR`)を廃した。
  v1は各boidに個体固有の固定探索方位（`memory[3]`、spawn時に均等分散）を
  割り当てて放射状に分散させる方式でheadless 10回中7勝だったが、ユーザーから
  「方向はboid自身に周囲を見て判断させたい、初期位置も拠点付近でランダムに
  したい」という要望を受けてv2に書き直した。v2はReynoldsのboidsアルゴリズム
  の分離則（Separation、視界内の他boidから離れる方向へ操舵）だけで拡散を
  自己組織化させる方式。v2の初期実装ではheadless 10回中3〜4回で**全boidが
  燃料切れのまま動けなくなる**不具合（拠点は見えているが密集による分離力で
  ピンポイントの`interactRadius`にたどり着けず孤立するデッドロック）が
  見つかり、`relay.ts`と同じ`lowFuel`パターン（低燃料時は分離力を無視して
  アンカーへ直進）を追加して解消。修正後はheadless **10回中10勝**（v1の
  7/10より改善）。
  → 上記の問い「補給所を随所に建てるならフェロモンの意義は薄いのでは」への
  現時点の答え：**この設定（拠点付近ランダムスポーン・WIN_AMOUNT=5）では、
  フェロモンなし・分離則による自己組織化的な拡散だけで十分機能する**。より
  厳しい条件（資源をさらに遠く・狭くする、スポーンをフィールド全体に広げる
  等）でも同じ結論が成り立つかは未検証。詳細は[docs/roadmap.md](roadmap.md)
  参照。
- 資源クラスタを1箇所から4箇所に増やした（コミット`59052e9`）。headless
  10回中10勝を維持したまま、勝利までのtickが653〜3941から542〜1431へ短縮。
- 呼称を「資源パッチ」から「資源クラスタ」に変更した。ユーザーの好みにより
  （「クラスタ」の方が「ソフトウェアの修正パッチ」に紛れず意味がストレートに
  伝わる、という理由。もともとコード内では`clusterCenter`という変数名を
  自然に使っていた経緯もある）。
