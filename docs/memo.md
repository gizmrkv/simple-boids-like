# 考えたいこと

現状（最新のコミットIDを付記して記録しておきたい）、boidはcargoがない状態で資源に触れると勝手に資源を取得して、資源を持っている状態で基地または補給所に触れると勝手に置いちゃう。
もしも、いずれ回収及び提出を制御したくなったらこの挙動を変える必要あり。特に勝手に拾っちゃうのは致命的かつユーザーにかなり面倒な実装を求めることになりそう。
雑な提案：boidに、もしも~~に触れたら勝手に回収するホワイトリスト変数と、勝手に基地または補給所に提出してよいかを制御するフラグ変数をもたせてこれを任意のステップで制御可能にする。
要検討：今後boidにどんな制御要素を追加していくかわからない状況でこれに決めてしまっても良いものか？保留にしたほうが良いか？


# 完了済み

- 広域探索（フェロモンなし版）を`scenarios/frontier.ts`として試作した
  （コミット`913458a`）。既存シナリオが全て使っていた「資源はこの方向に
  ある」という決め打ち(`EXPLORE_DIR`)を廃し、各boidに個体固有の固定探索
  方位（`memory[3]`、spawn時に均等分散）を割り当てて放射状に分散させ、
  ラダー(`ladder.ts`)の補給所連鎖建設をそのまま使って燃料範囲を拡張しながら
  探索する構成。
  headless 10回中7勝（勝利時tick 508〜1174）、残り3回は資源クラスタに
  一度も遭遇できないまま時間切れ。燃料切れで孤立したboidは0体。
  → 上記の問い「補給所を随所に建てるならフェロモンの意義は薄いのでは」への
  暫定的な答え：**フェロモンなし・補給所建設だけの分散探索は「時々失敗する」
  水準では機能する**。放射状の固定方位には視界(`viewRadius=60`)に対して
  角度の隙間があり（資源クラスタ距離での隙間が約170px）、探索の網羅性に
  構造的な限界がある。これがボトルネックなら、フェロモンより先に「発見時に
  周囲へ何か伝える」程度の軽い協調のほうが効果的かもしれない——次に試すなら
  どちらが良いかは未検討。詳細は[docs/roadmap.md](roadmap.md)参照。
